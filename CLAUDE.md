# Amparacán Wiki — project guide

A Wikipedia-style, **editable** wiki for the fictional island city-state of
Amparacán (1650s–2060s). It currently ships as a single self-contained
**Claude Artifact** (`wiki.html`) seeded with real data from the world's
Google Sheets. A future phase moves it to Next.js + Supabase + Vercel (schema
already provisioned; see below).

Live artifact: https://claude.ai/code/artifact/c68332cd-aa54-469e-be31-d3bf791a25af

## Repo layout
- `wiki_template.html` — the app: HTML/CSS + a self-contained JS SPA. Contains a
  `__WIKI_DATA__` placeholder where the dataset is injected. **Edit this**, not
  `wiki.html`.
- `wiki.html` — the built artifact (template + embedded data). Generated; do not
  hand-edit. This is the file published to the Artifact.
- `data/wiki_data.json` — the built dataset (entities, relationships,
  heads_of_state, chronology). Generated by `build_data.py`.
- `data/*.xlsx` — source exports (characters, portraits) shared by the world's author.
- `scripts/`
  - `parse_streets.py` — Streets sheet → `data/streets.json`
  - `parse_timeline.py` — Chronology sheet (saved text) → `data/timeline_raw.json`
  - `extract_portraits.py` — Characters xlsx → `data/portraits.json` (people-only, ships filtered)
  - `build_data.py` — combines everything (+ curated people/parties/geography) → `data/wiki_data.json`

## Build & publish
```
python3 scripts/build_data.py                 # rebuild data/wiki_data.json
python3 - <<'PY'                              # inject data into the template
import json; tpl=open('wiki_template.html').read()
o=json.loads(open('data/wiki_data.json').read()); o['revisions']=[]
d=json.dumps(o,ensure_ascii=False,separators=(',',':'))
open('wiki.html','w').write(tpl.replace('__WIKI_DATA__',d.replace('<','\\u003c')))
PY
node --check <(...)                            # sanity-check the appcode block
```
Then publish `wiki.html` via the Artifact tool (same file path keeps the URL).
Vercel (project `worldbuilder`, linked to the GitHub repo) deploys every push; `main` is production at https://worldbuilder-three.vercel.app. `vercel.json` turns on clean URLs, so the map is at `/map` (and `/map.html` redirects there); the wiki is `index.html` at `/`. The wiki's sidebar has a **3D map** link (`MAP_URL` in `wiki_template.html`): `/map` on the website, the map's Claude artifact (new tab) when the wiki runs inside Claude or as a file; building pages deep-link to `MAP_URL#<map_id>`. Rebuild `wiki.html` and `index.html` together after any template change (`scripts/build_html.py` has stale absolute paths; the inline snippet above works).
Editing persists via the `artifact` capability (`publish(html)`), with a
`localStorage` fallback for read-only viewers.

## Data model (per entity)
`entities` carry `slug, name, type (person|place|street|political_party),
description, bio, photo (data-URI)`. Type extras: people add
`birth_year/death_year, seasons[], occupation, origin_city, education, party
(slug), political_role, notable_for`; places add `place_type, population,
founded_decade, peak_decade, parent`; etc. Cross-links live in
`relationships`; `chronology` is `{y,label,text,refs[]}` with `[[wiki-links]]`
auto-woven into event text.

## 3D map (`map.html`)
A navigable 3D city (Three.js 0.160 from jsDelivr) raised from the author's
Illustrator map. Live artifact: https://claude.ai/artifact/3nuiTaptoGSx7TYf7cdecz
- `data/map/reorganise15.ai` — source map (PDF-compatible .ai). Artboard 3500pt,
  **1pt = 5m**. Layers used: Seas, Island, Elevation, Beaches, Canals, Streets,
  Pavement, Parks, Paths, Built. Ignored: `Scratch - island`, `Scratch - buildings`,
  Labels, Street names.
- `scripts/parse_ai_map.py` — dependency-free PDF content-stream interpreter →
  `data/map/map_data.json` (world metres, 0.1m-quantised, base64-packed). Fills are
  classified by colour (pink = building, beige = pavement, green = park, aqua = water).
  Building ids are stable hashes of footprint position (for future wiki links).
  `--stats` prints a per-layer colour/width census.
- `map_template.html` — the viewer (edit this). `__MAP_DATA__` placeholder.
  `STYLES` table drives façade/roof palettes (per-neighbourhood styles go here);
  heights are 3–5 floors for now. `window.amparacan` exposes `highlight(ids)`,
  `flyTo(x,z)`, `setMode()`, `buildings`, `stats()` for later search/wiki/editor work.
  `TOD` holds the dawn, day, dusk (default) and night presets (night adds the Milky Way); `T` cycles them.
  `WEATHER` (sunny, cloudy, rain, storm, fog) layers over it; `R` cycles it.
- Build: `python3 scripts/build_map.py [--reparse] [--preview /tmp/amparacan-map-preview]`
  then publish `map.html` via the Artifact tool, keeping its capabilities
  (`db` root rule read view / write owner, `user`, `sample`, `downloads`).
  Local preview: `.claude/launch.json` "map" serves `/tmp/amparacan-map-preview`
  (the repo lives under ~/Documents, which the sandboxed server can't read);
  locally edits go to localStorage instead of the db.
- **Edits live in the artifact db, never in the geometry**:
  `buildings/{bId}` and `features/{fid}` hold `{name, address, tags[], history, details,
  attrs{}, style{}}`. Feature ids are prefixed by kind: `pk` park, `pz` plaza, `wt` lake,
  `st` street, `pt` path, `cn` canal, `bc` beach (buildings are `b` + 8 hex). Style fields:
  buildings `facade (standard|neoclassical), wall, shutters, roof, roofType, floors, groundFloor,
  windows, doors, floorStyles, doorSide, awning, awningColor, porch, sign`; parks `grass, trees, treeType`; plazas `use (plaza|chinampa), paving, tint, trees (none|pleached), treeSides (letters of nesw, north = -z), curb (cm, 0–60), flagpole (bool)`; beaches `look (copacabana|natural)`; streets `paving, tint, lights, canopy` (0–100 slider: 0 none, ~30 palms, ~75 shade trees, 100 full canopy; the `trees` word is derived from it); paths `paving, tint`.
  `prompts/{pId}` `{bId (any target id), text, status: draft|queued|applying|applied|done|failed,
  result}`. `changes/{cId}` is the history log: `{at, targetId, kind, targetName, source:
  prompt|manual|claude-code, prompt, summary, category, tags[], fields[], before{style}, after{style}}`.
  "Apply now" restyles via the page's `sample` call; "Send to Claude Code" marks prompts `queued`.
  Prompts may carry reference `images: [{id, url, name}]` (artifact assets; read one with the
  Artifact tool, `action: read`, `path: <asset id>`). "Apply now" sends them to Claude
  (capabilities `sample: {images: true}`, `assets: {}`).
- Group prompts (from a multi-selection) carry `bIds: [...]` and `group: true`; group history
  entries have `kind: "group"`, `targets: [...]` and `before.styles: {id: style}`.
- **Processing the batch** ("process the map batch"): `ArtifactData list prompts`,
  implement each `queued` prompt (style fields via the target's doc, anything bigger in
  `map_template.html`), set the prompt to `status: "done"` + a short `result`, and add a
  `changes` entry with `source: "claude-code"`, a category and tags.
- **"Make this a pharmacy" means style it like a pharmacy.** Never suggest or set a name unless the
  author asks in words (name, call, rename). Tags (categories) only when asked (tag, categorise);
  otherwise, in a batch, restyle and you may ask the author whether to tag it. In the page,
  "Apply now" does the same: an unasked name is dropped (`ASKS_NAME`), unasked tags go to
  `suggest {tags}` (`ASKS_TAGS`) and `offerTags` asks "Also tag it …?" in the toast.
- Reopening: the page remembers the last selected/edited feature (localStorage) and flies
  back to it after a reload; `#<id>` deep-links any feature.
- **Re-importing from Illustrator**: `python3 scripts/build_map.py --source ~/path/new.ai`.
  The parser matches ids to the previous `map_data.json` (buildings: hash → overlap IoU ≥ 0.5 →
  centroid < 3m; other features: hash → nearby centroid with similar size) and prints
  kept/remapped/new/removed per layer; removed ids with edits show as
  "Edits without a building" in the page's Edits tray.

## Workflow conventions (standing — follow on every change)

### Pull requests — always write a detailed description
Every PR **must** have a thorough, well-structured description (never leave the
auto-generated stub). Refresh it on **every push** so it always reflects the
branch's full diff vs. its base. Structure:
- **Summary** — what this PR delivers, in a sentence or two.
- **Changes** — grouped by area (data pipeline, wiki UI, content), with specifics.
- **Live preview** — link(s) to see it running (the Artifact URL today; Vercel
  URLs once deployed there — see below).
- **Testing** — what was verified (headless checks, counts, screenshots).

### Vercel deploys — keep per-page preview URLs in the PR, always current
Once the app is deployed on Vercel, every push creates a new preview
deployment. On each push, update the PR description's **Live preview** section
to list the **current** deployment URL plus deep links to the **specific pages
that changed** in that push, each with a one-line note on what was updated. The
URLs must always be up to date with the latest push — treat updating them as
part of the push, not an afterthought.

_(Until the Vercel phase lands, the "Live preview" section carries the Artifact
URL, which is this project's live deployment.)_

### 3D map look (dreamy pass)
- Footprint corners are rounded (`roundedRings`, quadratic fillets with smooth normals); roofs have real eaves, fascia and soffits; parapets have a coping.
- Façade shader (`buildingMaterial`): limewash variation, rain streaks, exposed brick/stone patches, ivy and bougainvillea, louvred/closed shutters, window boxes, glazing bars, plank front doors (bay index packed in `aWall.w` thousands; `doorsOf(rec)`), terracotta barrel tiles, paver terraces. Roof clutter in `roofClutter`.
- Street furniture (`addStreetFurniture`, instanced per 400 m chunk, shown near the camera by `updateFurniture`): lamp posts with night halos and light pools, benches, bins, bollards, planters, potted plants at doors, canal railings, plaza fountains.
- Post-processing: bloom + split-tone grade per time of day (`TOD[...].post`, `applyPost`). Rendering goes through `post.composer`.
- Fidelity pass (reference-image look): painterly sky (fbm cumulus in the sky shader, `uCover` per weather), brush-stroke walls with quoins and warm-below/cool-above grading, patched/mossy barrel-tile roofs, balcony planters, trailing vines, awnings, drainpipes, AC units (`buildingExtras`), overhead wires and laundry (`addWires`), curved-frond palms and cypresses, weathered paving textures, leaf-clump `blossom()`s dappled in the shader (`aWall.z = -7`).
- Parks: `rebuildParkTrees` plants trees, shrubs and flowering bushes (parks are planted over the pavement underlay, using `world.occP`); `updateGrass` streams swaying grass blades in 32 m chunks around the camera (`windPatch` + `WIND`, which also sways palms, trees and bushes); `addStreetFurniture` places park lamps, benches, bins, picnic tables and drinking fountains. Each `windPatch` needs its own `customProgramCacheKey`.
- Performance: quality tiers (`TIERS`, `Q`, `applyQuality`; Auto adapts to frame time, the top-bar button cycles Auto/Low/Medium/High, choice saved in localStorage `amparacan-map-quality`). Balconies, vines, pipes, AC units, laundry, awnings, stoops, rooftop clutter go to 250 m detail cells (`world.tileCells`, shown near the camera by `updateDetail`), built lazily (see the load-time bullet below). Vegetation lives in 250 m cells with a full model near and a cheap proxy far (`treeMeshes`, `updateVeg`); bushes only draw near. Wires, string lights and detail hide from high altitude (`updateCull`). The façade/roof shader skips its noise beyond a distance. Profile first: the original slowdown was 190k park plants, not the buildings.
- Layers menu (`layers`, `LAYER_ORDER`, `initLayers`): which kinds of thing hover/click/box-select can pick, saved in localStorage `amparacan-map-layers`; `featureAt(x, z, tol, true)` filters by it. A building that isn't pickable still blocks the click.
- **General requests never override specific ones.** A style field set on one item by itself (a building's floors, a plaza made a chinampa, a street's canopy) is that item's own. Group edits (box/shift selection, group prompts, "reset look") work around it and only change fields they wrote earlier, tracked in the doc's `auto` map (`isOwn`, `markOwn`, `markAuto`). Docs from before `auto` existed count every style field as their own. When processing queued batch prompts, or when a request like "trees and grass in all parks" is made in a session, do the same: skip fields already set on individual items and say which were left alone.
- The Select area button is gone: Shift-click, Shift-drag, or press B to turn on drag-to-select.
- Search (`initSearch`, `runSearch`, `categoryMap`): top-left box; matches name, address, tags, details, history, attributes and ids across buildings and features; Enter or a click flies there and selects it (`focusTarget`). The Categories button lists every tag on buildings with counts; switching tags on (or typing a query) lights up the matching buildings (`highlight` glow plus tall light beams, `setBeacons`). `/` or ⌘/Ctrl K focuses it. Category = tag, so a building appears under “school” once it is tagged `school` (singular/plural both match in text search).
- Walk drop: drag the Walk button onto the map (`initPegman`, `nearestRoad`) to start walking on the nearest street or path, facing along it (Street View style). Roof gardens and timber terraces (`rec.roofKind`, `roofGarden`, `insetFootprint`) go on roughly 45% of flat roofs whose colour hasn't been set by hand; the lawn/deck surface is in the main tile mesh (`aWall.z` -8 / -9), the shrubs, pergolas and parasols are distance-culled detail.
- Street trees skip any pavement narrower than `SIDEWALK_MIN` (2 m of clear ground between the kerb and the nearest wall, `narrowWalk`).
- Contact shadows and lighting: the scene is drawn into its own colour+depth target (`post.sceneRT`), a depth-based AO pass and a depth-aware blur darken creases, kerbs, trunk bases and eaves (Medium 8 samples, High 12, off on Low; strength and S-curve per time of day in `TOD[...].post`). The depth buffer is logarithmic, so view depth = (far+1)^d - 1. Anti-aliasing is FXAA (MSAA can't coexist with the depth target). A warm `bounce` light fills the side away from the sun. Never let a pass draw into the target whose depth texture it samples (WebGL feedback loop → black screen).
- Streets stay clear: street trees, furniture, door pots and countryside trees are rejected on any street, path or street-area surface (`roadAt`, which checks every street, not just the one a tree belongs to). Wide boulevards no longer get a central row of trees. `hardAt` adds canals and lakes for grass, park trees and bushes.
- Time of day, Weather and Graphics buttons are dropdowns (`initDropdowns`, one shared `#opt-menu`); the T and R keys still cycle time of day and weather.

### Moved buildings after an Illustrator re-import
`python3 scripts/build_map.py --source NEW.ai` (or `--reparse`) now also writes `data/map/reimport_moves.json`: old building ids that no longer exist whose exact footprint shape (any position, rotation or mirror) reappears among the new buildings (`find_moves` in `parse_ai_map.py`). Each entry has the old id, where it was, and every candidate new id (`unambiguous` is true only when there is a single candidate and nobody else claims it).
**Never move a design silently.** After a re-import: list `buildings/` in the db (`ArtifactData`), keep only the old ids that actually have edits, show the user each proposed pair (name or tags, old place → new place, same footprint) and every candidate when ambiguous, and wait for their yes. For each confirmed pair `old → new`: copy the old doc to `buildings/<new>`, delete `buildings/<old>`, repoint `changes/*` (`targetId`, `targets`) and `prompts/*` (`bId`, `bIds`), update `map_id` in `data/map/building_attrs.json` so the wiki page follows, then republish. Anything unconfirmed stays in the page's “Edits without a building” list.
- Park lawns darken with altitude (`world.parkDim`, `updateCull`): once the trees that shade them are culled (`vegAlt` per tier, so earliest on Low) the bare lawn would read lime green.
- Character (`makeCharacter`, `poseCharacter`, `solveArm`): a 1.82 m jointed figure. `rig` (pelvis at `HIP`) → `spine` → `head`/arms; legs hang from `rig` (`legs[i].thigh/knee/ankle`, `arms[i].sh/el/wr`). Cloth is parametric surfaces (`surf`, `limb`) with drapery folds; the face is a displaced ellipsoid (`FEAT` table of gaussian features, colours in vertex colours); hair is a scalp cap plus short strands. Walking uses FK with phase `player.walkPhase`; arms use a two-bone IK (`solveArm`); coat skirt, queue and plume are damped springs (`u.sp`). Photoreal would need a real rigged glTF model.
- Character model: `data/character/barbossa.glb` ("BARBOSSA" by ultradeath6700, CC-BY-4.0 — credit is in the Controls panel; keep it). It has no skeleton, so `loadCaptain` builds one from landmark joints (cm → m, `S`) and auto-skins by capsule distance (coat anchored to the pelvis). `build_map.py` embeds it base64 in `#char-glb`; the procedural `makeCharacter` is the fallback until it loads. The same `poseCharacter`/`solveArm` code drives both (arms use rest axes `r1`/`r2`). The arm landmarks in `J` carry z (the model's forearm angles forward), so lowered hands hang at his sides rather than in front. Posture: the spine is tilted back (-0.13) because the model stoops at rest; `run` is 0 at walking pace (4.2 m/s) and 1 at 9 m/s; a walk swings straight arms gently. A run leans the body ~0.13 rad forward, drives the knee forward (hip bias), flexes the stance knee and kicks the heel up, and uses a runner's arm action computed by forward kinematics (upper arm swinging from the shoulder, elbow held near 90°, swinging around a point well behind the shoulder, held out a little, so the hands stay at his sides; the thighs angle inward so the feet land close together). A run also takes longer strides: the step cadence drops by up to 32% (`player.walkPhase` rate) while the leg swing grows (`amp` +0.36·run), and the arm pump swings ±0.52 rad about -0.6. The walk is approved as is: running tweaks go through `P.run` so they never touch it and handed to `solveArm` with the elbow as the pole. A properly rigged model (e.g. Mixamo auto-rig) would deform better.
- Measure tool (`measure`, `toggleMeasure`, `placeMeasure`, key X / the Measure button): click two points in 3D (roofs and walls count, else the ground plane) or in the 2D plan; an SVG overlay draws the line and an HTML label shows the horizontal distance in metres, plus the straight-line distance and height difference when they differ. A third click starts over; Esc or X exits.
- Distant parks: when the real trees are culled (`vegAlt`), the park overlay shader (`overlayMesh` with `dim`, uniform `uDeep` = `world.parkCanopy`) deepens the lawn to a rich green (a deep tint that keeps the lawn's own texture), and a few groves/orchards (`groveGeometry`, `groveMeshes`, placed per park in `rebuildParkTrees`) stand in at tree height as ruffled leafy crowns; they show when the camera is far (`updateVeg`, role `grove`).
- Undo / redo (`undo`, `trackUndo`, `undoEdit`, `redoEdit`; ⌘/Ctrl Z, ⇧⌘Z or Ctrl Y, and the buttons under Measure): `saveDoc`/`deleteDoc` record every write to `buildings/` and `features/` docs; writes within 0.45 s form one step (group edits, slider drags). Undo restores the previous doc (or deletes it, back to the generated look) and re-emits it. Session-only; the history tray log is not rewound.
- Beaches are pickable across all their sand: `sandStrip` returns the sand outline per beach (`f.sandRings`), `buildBeaches` stores it, widens `f.bbox` and registers the grid cells, and `featureAt` tests it as well as the line.
- Sound and music (`AUD`, `audioInit`, `audioTick`, `musicTick`; buttons `#snd` and `#mus` in the top bar, saved in localStorage, started on the first click/key because browsers require it): all synthesised with Web Audio, no files. Sound = breeze (louder with speed/altitude/storm), gulls (day, fair weather), waves (louder as `shoreDistance` falls), rain and storm hiss, and thunder (`thunder()` is called from the lightning flash in `applyWeather`/`stepWeather`). Music = a slow generative ambient piece: chord pads, a sub drone and glassy notes through a long reverb and echo. `window.amparacan.audio()` reports state and level for checking.
  Waves are discrete events (`waveEvent`, one every 6–12 s while near the sea): a building swell, a slow build, a deep crash with a sub-bass boom (no foam hiss) and a backwash dragging down the shore, over a quiet continuous surf bed.
- Place-aware ambience (`ambienceInit`, `ambienceTick`, `audioEnvSample`): every ~0.4 s the player's surroundings are sampled (park/tree cover, canal and fountain distance, enclosure by buildings = `narrow`, nearest wall, swimming). From that: songbirds/parrots/doves (busiest at dawn, building slowly, then dusk) in parks and tree-lined streets, leaf rustle and palm clacks under canopy, canal lap, a fog low-pass plus foghorn with echoes (fog; rarer in mist), night owl / distant song (infrequent), a very soft fire crackle at dusk and night only within 6 m of a wall, a dawn rooster, reverb that grows with `narrow`, a muffled low-pass world plus splash and bubbles when swimming, and a wind roar plus whooshes past buildings when flying. Ground sounds fade with altitude (`gf`).
- Houseboats (`boatGeometries`, `initBoats`, `stepBoats`): ~1,000 London-style narrowboats built lazily on the first frame, all moored in lines along the water's edge: bank by bank on every canal (every 15–24 m, skipping bends and bridges, and keeping every canal junction clear: a boat is dropped if any of three samples along its length falls near another canal), and in marinas on the shores of the narrow south-coast inlets (found by scanning `H`, z > 1500): from the middle of each marina `initBoats` walks along the quay both ways dropping a boat every 3 m, all side by side with their bows to the quay (perpendicular to the shore, one rank, never nose-to-tail), using an occupancy grid so they never overlap. Instanced meshes: tinted body (hull + cabin), glowing windows (emissive follows `NIGHT`), window frames, three roof/detail variants. They rock on the water, some have chimney smoke (a `Points` cloud), and count and draw distance follow the quality tier. (The code still supports `cruise` and `drift` kinds, unused.)
- Sound mix (`MIX`, `initMixer`, `mx(k)`): Ctrl-click (or right-click) the sound button `#snd` for `#mix-panel`, one volume slider (0–150%, double-click resets) per sound group, saved in localStorage `amparacan-map-mixvol`. `mx(k)` returns the group's volume (1 = normal) and every sound control point multiplies by it; there is no separate mixer button.
- Dawn and dusk atmosphere: the dawn and dusk vapour is a sky-shader effect (`uVapour`/`uVap`: three drifting, sinuous bands of luminous haze near the horizon, set in `applyWeather`; no city mist, nothing blurs the camera); `addPetals`/`stepPetals` waft ~240 purplish petals (a `Points` cloud, 80 m box around the camera, below 160 m altitude, hidden in rain and fog).
- Street/path junctions (`pathBlend`, `ribbonOverlay` `blend`): where the end of a street or path runs into another street or path (within 4 m of its edge), the ribbon's vertex colour eases into that surface's colour over its last ~9 m, so differing paving tints don't meet in a hard line. Editing a street or path rebuilds both kinds so the blend follows.
- Music is a lofi piece modelled on the user's reference video (analysed in-browser: ~72 BPM, D major, Dmaj7/Gmaj7/Bm7/F#m7/Em7/Asus chords, soft plucked/flute melody around D5, dark top end above ~5 kHz, weak beat). `musicTick` schedules 8th-note steps (`lofiStep`, swing, 8-bar loop `LOFI`) of electric-piano chords (`epNote`), kalimba plucks with a dotted echo (`pluckNote`), a breathy flute (`fluteNote`), bass, a quiet pad, a soft kick/snare/hats and vinyl crackle, all through `AUD.lofiBus` (low-pass 4.6 kHz, small room, echo). The old ambient pad/glass piece was removed.
- Free street/path ends: an end that doesn't run into another street or path (`f.free` from `pathBlend`; e.g. a street stopping in a plaza or open paving) fades to transparent over its last ≤7 m (`aFade` vertex attribute, `fadeAt` in `ribbonOverlay`, `overlayMesh(..., fade)` makes ribbon materials transparent) so the pavement beneath shows through instead of a hard rounded cap.
- Sunk-building foundations (`ghosts`, `ghostOf`, `stepGhosts`, called from `stepAnim`): while a building has sunk out of the way of the character or camera, a low plinth (`PLINTH_H` 0.32 m, the building's wall colour, darkened) traces its footprint and a terracotta tiled floor fills it, both fading with the sink; built lazily per building and disposed once it has risen again.
- Solar panels (`solarPanels`, `SOLAR_PCT`, `rec.solar`): about 20% of flat roofs (1,611 of 7,981) carry rows of panels tilted ~20° to face south (+z), laid parallel to the longest wall and kept 1.25 m inside the parapet. Only roofs with no garden or deck, area > 45 m², and no roof colour set for that building by hand. Panels, their backs and the silver frame lines all go in the main building mesh so they read from the air.
- Fly take-off pose: `poseCharacter` gets `climbing` (the climb key, Space/E or the touch up-pad, held in fly mode). Entering fly mode (`P.launch`, 0.9 s) raises both arms halfway, out to the sides (`P.launchK`, both arms) — never the full overhead arm. While climbing from a hover, `P.up` follows a critically damped spring (`P.upV`; eases in, ~1 s up) and his right arm (`arms[0]`, his -x side, since he faces +z) is raised straight overhead with the head tilted up; it starts lowering the moment the climb stops and settles over ~1 s. The arm only rises for a climb from a hover or slow drift: when he is already flying forward (`fwd = smooth(4, 12, hv)`), a climb instead eases `P.climbF` up and tilts his body nose-up along the climb (rig pitch −0.55·climbF·lean) with the head lifted.
- Wind on the water (sea shader in the terrain setup): wind direction `Wd`; gust patches (`gust`, cat's paws) drift downwind at ~7 m/s, darker and more ruffled; long calm `slick` streaks lie along the wind and reflect more sky; ripple strength `rip` scales the small-ripple terms and the downwind wavelets `wr`.
- Houseboat variety (`variety` in `initBoats`, its own generator `vr` so the layout doesn't change): ~22% are widebeams (instance z-scale `b.wid` 1.45–1.8; canal ones only on canals ≥ 11 m wide and set further from the bank; marina ones checked against the occupancy grid at their real width), and ~8% have a second storey over the back cabin (`b.two`, `b.us`; instanced `upBody` tinted `b.tint2`, cream `upTrim` with a roof rail, and `upWin` windows that glow at night).
